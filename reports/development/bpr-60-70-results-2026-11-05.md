## Frozen experiment

BPR pairwise-loss two-tower; same tower architecture as the preceding run; 32-dimensional embeddings, batch 512, three epochs, Adagrad at 0.05, one uniform sampled negative per positive per epoch, random seeds 42/43/44, rejecting items the user rated in the training period. Positive target is rating >= 4. Training used 15,000,057 rows and 7,479,996 positive pairs; the following temporal validation window contained 2,500,009 rows. The training catalog had 14,324 rated items, of which 13,173 were indexed. The script-reported training time was 278.639 seconds. Loss by epoch: 0.153892, 0.140931, 0.214885.

The split boundaries were frozen before this run. However, BPR was selected after viewing the 70/80 development result. This is a temporal replication of that selected method, not an independent test of model selection.

## Decision and limits

**Decision: do not promote BPR.** It did not beat the matched popularity baseline on this window. The run does not establish performance on an untouched evaluation: the objective was selected after inspecting the 70/80 results, and this 60/70 check is a development replication. Ratings >= 4 are a preference proxy, not clicks or CTR; unrated items used as negatives may be unknown preferences. The result does not validate the required downstream ranking stage, online A/B test, CTR, or production serving. The API remains the popularity-only demo described in scripts/recommendation_api.py.

No raw MovieLens data was downloaded or changed for this run. The Colab notebook cells were edited for script transfer, preflight, execution, and metrics readout. The temporary script and model/run outputs were written under /content; these outputs are ephemeral and are not part of the local package.
