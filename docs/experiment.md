# Local A/B experiment prototype

The opt-in native API experiment assigns a participant consistently to A (ItemKNN order) or B (experimental DCN request) using a keyed hash. A B assignment can still return ItemKNN when the ranker falls back; each event records both the assigned variant and the actual strategy. The ranker has not outperformed ItemKNN in its recorded development comparison.

To enable locally, configure ItemKNN and the experimental ranker as in `docs/api.md`, and set both `NEXVIA_EXPERIMENT_DB` to a writable SQLite file and `NEXVIA_EXPERIMENT_SECRET` to a private value of at least 16 UTF-8 bytes. Keep the same secret for the life of the experiment or assignments can change. Do not commit the secret or event database. The API has no user authentication or experiment administration controls; this prototype is for a trusted local environment.

- `POST /experimental/ab/recommend` accepts `participant_id`, MovieLens `user_id`, `history_item_ids`, and `limit`. The caller must ensure the user ID and history correspond. It returns the assignment, an impression ID, and the recommendation response. The server records a **served response**; it does not know whether the browser actually rendered the items.
- `POST /experimental/ab/click` accepts that `impression_id` and an `item_id`. It accepts only items included in that response and ignores a repeated click on the same item for the same response.
- `GET /experimental/ab/summary` reports participants, served responses, item positions served, distinct item clicks, item clicks divided by item positions served, and actual strategies for each assigned arm. This item CTR is a descriptive count; it is not a user-level causal estimate or a statistical significance test.

Only a keyed hash of the participant ID is stored, not the raw ID. The database is local and can still contain linkable pseudonymous activity. Use anonymous IDs and avoid entering personal information. Client behavior is unauthenticated and can be fabricated. User-level analysis, sample-ratio checks, rendering confirmation, data governance, and an appropriately designed live study would be needed before drawing an online conclusion. No real-user A/B result or CTR has been collected here. Synthetic checks are not study outcomes. See the [controlled experiments guide](https://exp-platform.com/Documents/GuideControlledExperiments.pdf) and [Google's discussion of ranking and position bias](https://developers.google.com/machine-learning/recommendation/dnn/scoring).
