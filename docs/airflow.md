# Experimental retraining workflow

`airflow/dags/manual_retraining.py` defines a manual-only Airflow 3 DAG: preflight, train, and review. It has no automatic schedule, retries, or automatic model promotion. Each run uses a new directory derived from its run ID. The preflight checks the ratings file against the split report's SHA-256 and checks timestamp order; the review step checks that the result metadata reports the same data and cutoffs and `test_evaluated: false`. Metadata alone does not prove the test data was never accessed.

The Airflow environment must have the project on `PYTHONPATH` and define `NEXVIA_PROJECT_ROOT`, `NEXVIA_RATINGS_PATH`, `NEXVIA_SPLIT_REPORT`, `NEXVIA_RETRAIN_OUTPUT_ROOT`, and `NEXVIA_RETRAIN_PYTHON`. The selected Python interpreter must already have the retrieval dependencies. The command uses the streaming pilot with a 500,000-interaction training-sample cap, up to three interactions per selected user, three epochs and 2,000 evaluation users. The sampler scans the source file to apply timestamp filters, so the interaction cap does not limit the number of input rows scanned or total memory use.

The official Airflow 3 standalone container was started on 5 November 2026. It listed `nexvia_manual_retraining` and reported no DAG import errors. The DAG remained paused; its preflight, training, and review tasks were not executed. Separately, the helper's preflight and metadata checks were tested with small fixtures and a stubbed subprocess, and the DAG's Python syntax parsed. No training was triggered. The previously used split and the pilot model are development artifacts; running this workflow does not establish an improvement, and every result requires review. For Airflow's DAG and TaskFlow concepts, see the [official tutorial](https://airflow.apache.org/docs/apache-airflow/stable/tutorial_taskflow.html).
