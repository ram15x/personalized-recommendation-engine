## Assignment brief

The portal assigns **AIML-03: Large-Scale Personalized Recommendation Engine**. Its description asks for a two-stage recommender: retrieve a few hundred candidates, then rank them. The detailed instructions ask for:

1. MovieLens 25M or Amazon Reviews, cleaned and split by time.
2. Spark interaction tables and features for user history, popularity, and categories.
3. A TensorFlow Recommenders two-tower model for user and item embeddings.
4. FAISS indexing of item embeddings.
5. A deep ranking model, with DCN or Wide & Deep given as examples.
6. Popularity and content-based cold-start fallbacks, with Redis caching.
7. Triton model serving, Airflow retraining, and a simple online A/B comparison of two ranking models. The brief names NDCG, Recall@K, and click-through rate as measures.

The portal's required stack names TensorFlow Recommenders, FAISS, Redis, Apache Spark, Airflow, and Triton Inference Server. The submission checklist also asks for a working demo, GitHub repository and setup instructions, architecture and data/API documentation, results, a 10-minute presentation, and an individual reflection. The portal specifies one final Google Drive submission for both assigned projects; this note does not submit anything.

Overall retrieval Recall@100/200/500 was **0.2331 / 0.3102 / 0.4485**, below popularity at **0.2515 / 0.3354 / 0.4893**. The panel has **570 users with prior history** and **1,430 true cold-start users**. Of the 570 warm users, 528 had a learned embedding and 42 used popularity fallback. Index coverage limits the ceiling, but most indexed positives still fail to reach the retriever's top 500; this indicates the saved model does not rank many available positives highly enough for the candidate set. This is an inference from this reused validation diagnostic, not an independent conclusion about generalization. The script recomputed inner products with NumPy from the saved vectors; it hashed but did not load the FAISS binary, so exact binary-index equivalence is not verified. ## Research basis for the two-stage design

TensorFlow Recommenders describes retrieval as selecting hundreds of candidates from a large catalog, followed by a ranking model that narrows them to a shortlist. Its retrieval tutorial also evaluates top-K retrieval against a candidate catalog. This supports measuring candidate recall and coverage before a ranker is treated as useful: [TFRS retrieval tutorial](https://www.tensorflow.org/recommenders/examples/basic_retrieval), [FactorizedTopK metric](https://www.tensorflow.org/recommenders/api_docs/python/tfrs/metrics/FactorizedTopK), and [TFRS ranking tutorial](https://www.tensorflow.org/recommenders/examples/basic_ranking).
