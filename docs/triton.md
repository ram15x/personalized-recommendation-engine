# Experimental Triton ranker interface

`triton/model_repository/dcn_ranker/` contains a Triton Python backend model configuration and implementation for the saved experimental DCN ranker. The model expects aligned, nonempty vectors `USER_ID` (INT64), `ITEM_ID` (INT64), and `ITEMKNN_SCORE` (FP32), with one user per request. It returns `RANK_SCORE` (FP32) and `SUPPORTED` (BOOL). A false `SUPPORTED` entry means the item is outside the saved vocabulary; its score placeholder is zero and must not be used for ordering. Unknown users and malformed inputs return errors. The caller is responsible for candidate generation and fallback ordering.

The Python backend expects the project code on `PYTHONPATH`, a compatible TensorFlow installation in the Triton Python backend environment, and `NEXVIA_EXPERIMENTAL_RANKER_DIR` pointing to the saved model and mapping. The adapter verifies their hashes against the artifact manifest before loading. Triton does not supply the ItemKNN features itself.

The backend contract was checked with a Python stub; an actual Triton server, compatible backend environment, model load, and network inference are **not verified**. This repository contains no tested Triton deployment command or image. The model did not beat ItemKNN in the saved development comparison and is not a production model. See [NVIDIA's Python backend documentation](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/python_backend/README.html) and [model configuration guide](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/user_guide/model_configuration.html).
