Movie recommendation research

From watched movies to a ranked shortlist.

A practical study of recommendation pipelines using temporal evaluation, a popularity baseline, item-to-item retrieval, and experiments with learned retrieval and ranking.

System at a glance

Candidate retrieval

ItemKNN cosine similarity finds related titles from a liked or highly rated movie history. Popularity provides a fallback when the history cannot be used.

Transparent fallback

Users can also request a list by genre. This path uses movie metadata and is separate from collaborative filtering.

Engineering

FastAPI serves recommendations; a small browser interface calls the API. Docker Compose runs the local demo and Redis cache.

Workflow

PrepareBuild time-aware training and evaluation windows from MovieLens ratings.
CompareMeasure popularity and retrieval using ranking metrics and paired user comparisons.
ServeRun the selected ItemKNN candidate with explicit fallback behavior in the local API.
InspectKeep experimental learned models separate when they do not pass the comparison gate.

How to read the results

The project reports offline ranking measures such as Recall@K and NDCG@K. Movie ratings are preference proxies, not click events. Development windows were reused during model selection, so they are not independent confirmation. Online A/B results and click-through rate are not claimed.

Try it locally

Clone the repository, obtain MovieLens directly from GroupLens under its terms, prepare the local serving artifacts, then follow the Docker Compose instructions in the README. Dataset and model files are intentionally excluded from this public site and repository.
